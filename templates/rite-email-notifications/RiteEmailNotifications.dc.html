Rite design system · Notifications

E-mail notification templates

One send-ready shell every RiteSuite module writes into, plus nine notification types built on it. Table-based, inline-styled, no web fonts and one hosted logo — they survive Outlook, Gmail and Apple Mail as sent.

Shell anatomy
01Deep Forest header — reversed Rite lockup left, module name right in Sage caps.
024px signal rule — Mint normally, Ember for failures, Amber for overdue.
03Eyebrow → headline → standfirst — the brand triad, sentence-case headline.
04One or two content blocks — details, table, timeline, metrics, list or code panel.
05One primary action — bulletproof green button, optional ghost second.
06Footnote, then footer — support contact and the confidentiality notice.

Mail clients get literal hex, not tokens — that is the one place the system is written out by hand. Poppins and IBM Plex Mono cannot be used either: body type falls back to Arial/Helvetica, figures and IDs to Courier New, so the mono-for-scannable-values convention still holds.

 Rules
✓ One action per notification. If there are two, the second is a ghost button, never a second green one.
✓ State the fact in the headline, including the identifier. "Batch ${batchId} is waiting on your approval", not "You have a pending item".
✓ Say what happens next and by when — SLA, expiry, escalation — in the footnote.
✗ No emoji, no exclamation marks, no "Dear User". The reversed lockup is the only image.
✗ No Mint as a surface — it is the 4px rule and the OTP figure, nothing larger.
✗ Never more than two content blocks; move the rest into the app.

Implementation

Wiring it into an application

Placeholders

Every variable is ${field} — substituted server-side before send. Three are shell-level and present in all ten files:

${moduleName} — header right, caps
${preheaderText} — inbox preview, ~85 chars
${recipientEmail} — confidentiality line
 Adding a new type
01 Copy rite-notification-shell.html.
02 Replace the triad, pick at most two blocks from the pattern comments.
03 Change the 4px rule colour only for failure or overdue states.
04 Keep the footer block byte-identical across every module.
 Before you ship
Send a plain-text alternative part — same facts, same URL, no markup.
Keep each file under 100KB so Gmail does not clip it.
Point every URL at an absolute https link; no bare anchors.
Host rite-logo-lockup-white.png on your CDN and point each header <img> at that absolute https URL — alt text is already set.
